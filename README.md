# bookstore — 地元で買う

オンライン書店の書籍ページに、**大学生協**（研究費／私費の指定つき）または
**地元書店**への注文メール下書きを作るパネルを添えます。
Chrome 拡張とローカルページの両方で動きます。

研究者が本を買うとき、Amazon で見つけてそのまま Amazon で買ってしまうのは、
生協や地元書店で買うには「別のサイトを開いて書名を打ち直す」手間があるからです。
その手間の差だけで購買先が決まってしまうのを、埋めるためのツールです。

**自動発注はしません。** 人が最終確認して送るための下書きを作るところで止めます。

対応サイト: Amazon（.co.jp / .com）・楽天ブックス・紀伊國屋ウェブストア・
丸善ジュンク堂ネットストア

## インストール

Chrome ウェブストアには出していないので、**開発者モードで読み込む**形になります。

1. [Releases](https://github.com/ykfrkw/bookstore/releases) から
   `bookstore-<version>.zip` をダウンロードして展開する
2. Chrome で `chrome://extensions` を開き、右上の**デベロッパーモード**を ON にする
3. **「パッケージ化されていない拡張機能を読み込む」**で、展開したフォルダを選ぶ

> デベロッパーモードで拡張を入れると、Chrome の起動ごとに
> 「デベロッパーモードの拡張機能を無効にする」という警告が出ます。
> 拡張の性質上ウェブストア審査を通す予定がないため、現状はこの形です。

### 初期設定

拡張の**「詳細」→「拡張機能のオプション」**から、
最低限これだけ入れてください。未入力のままだとメール作成時に弾かれます。

- **依頼者** — 氏名・所属・自分のメールアドレス
- **注文先** — 生協または書店の宛先メールアドレス（複数登録できます）
- **財源** — 研究費で買う場合のみ。科研費などの名称・課題番号・予算代表者

注文先は複数保存でき、よく使うものを既定に設定できます。
**最初は宛先に自分のメールアドレスを入れて試すことを勧めます。**
実際の生協・書店に誤って送ることなく、届いた本文をそのまま点検できます。

## 使い方

1. 対応サイトの書籍ページを開くと、購入ボックスの近くにパネルが出ます
2. 注文先と支払区分（研究費／私費）、冊数を選びます
3. 「今すぐ注文メール」を押すとメーラーが開きます。**内容を確認してから
   送信してください**

メーラーの開き方は本文の長さで 2 通りに分かれます。和文は `mailto:` の
長さ制限（実質 2000 文字前後）に当たりやすいためです。

- **収まる場合（3 点程度まで）** — 本文の入った状態で開きます。貼り付けは
  不要です。この場合は長さに収めるため、著者・出版社・挨拶などを省いた
  **簡略版の文面**（書名・ISBN・冊数・価格は残ります）になります。
  そのことは画面上に表示されます
- **冊数が多い場合** — **本文がクリップボードにコピーされ**、宛先と件名だけの
  メーラーが開きます。本文欄に貼り付けてください（⌘V / Ctrl+V）。
  この場合は省略のないフル版の文面です

### メーラーが開かないとき

「今すぐ注文メール」を押しても**何も起きない**場合、ブラウザに `mailto:` を
渡す先が無い可能性が高いです。Chrome は `mailto:` を登録済みのハンドラか
OS の既定メーラーに投げるため、どちらも無いと無反応になります。

- Gmail を使っている場合は `chrome://settings/handlers` を開き、`mailto` の
  ハンドラに Gmail があるか（「許可」になっているか）を確認してください。
  無ければ https://mail.google.com を開き、アドレスバー右端のハンドラアイコンから
  許可します
- パネルは、開けなかったと判断すると 1〜2 秒後に「Gmail で開く」を出します。
  そこから開くと**次回以降も Gmail で開く**設定になります（設定画面の
  「メールの開き方」でいつでも戻せます）
- 設定の「メールの開き方」で最初から **Gmail** に固定することもできます。
  「既定のメーラー」に固定した場合、この案内は出ません
- **`mailto` のハンドラを登録済みの場合、既定の「自動」では「今すぐ注文メール」が
  現在のタブをそのハンドラ（Gmail など）に遷移させます。** 開いていた書籍ページは
  残りません（ブラウザの「戻る」で戻れます）。「自動」は、メーラーが開かなかった
  ことを推定するために新しいタブを使えないためです。
  **書籍ページを残したい場合は、設定の「メールの開き方」を「既定のメーラー」に
  固定してください。** 固定すると推定をしなくなるので、新しいタブで開きます
  （代わりに上の「Gmail で開く」の案内は出なくなります。また、OS のメーラーを
  使っている場合は空白のタブが残ることがあります）

複数冊をまとめて 1 通にしたいときは、各ページで「カートに入れる」を押してから、
ツールバーのアイコン →「1 通にまとめてメール」。

生協の公費 WEB フォームから出す場合は、「備考欄をコピー」で
財源・予算代表者・配達先の 1 行が取れます。

## プライバシー

- **入力した設定・書籍リストは、すべてブラウザ内（`chrome.storage` /
  `localStorage`）にのみ保存されます。** 外部のサーバーには保存しません。
- **既定の状態で外部へ出るのは、書誌情報を引くための
  [openBD](https://openbd.jp/) への ISBN 問い合わせだけです。**
  送るのは ISBN だけで、氏名・所属・財源・メールアドレスは送りません。
  例外は 1 つで、次の「Gmail で開く」を選んだ場合です。
- **「Gmail で開く」を選んだ場合だけ、下書きが Google に渡ります。**
  作成画面の URL に宛先・件名・本文を載せて開くため、本文に含まれる氏名・所属・
  財源（科研費の課題番号を含む）が URL として Gmail に渡ります。これは
  **自分のメールアカウントに下書きを渡している**のであって、このツールが
  第三者へ送信するわけではありません（メールを Gmail から送る以上、
  送信時にはいずれ同じ情報が Google を通ります）。
  既定の「自動」「既定のメーラー」では渡りません。**既定では openBD 以外と
  通信しませんが、Gmail を選んだときだけ例外になります。**
  この URL は Chrome の履歴にも残ります（同期していれば同期されます）。
  渡したくない場合は、設定の「メールの開き方」を「既定のメーラー」にしてください。
- 閲覧履歴・ページ内容の収集、分析・テレメトリの類は一切入れていません。
- 拡張が要求する権限は `storage`（設定の保存）と、対応書店ドメインおよび
  `api.openbd.jp` へのアクセスのみです。

## ローカル版

拡張を入れずに使う版です。Amazon の URL でも ISBN でも、1 行 1 件で
貼り付ければ同じ注文メールを作れます。

```bash
npm run local     # http://localhost:8787 で開く
```

`file://` で直接開くと ES module が CORS で弾かれるので、必ず上記コマンド
（http 経由）で開いてください。

## 開発

```bash
npm test          # node:test。ネットワーク不要
npm run dev       # src/core の変更を拡張ディレクトリへ自動同期
npm run local     # ローカル版を http://localhost:8787 で開く
npm run build     # dist/bookstore-<version>.zip
```

ソースから拡張として読み込む場合は、`npm run sync` のあと
`chrome://extensions` で **`src/adapters/extension`** を指定します。

ロジックは `src/core/` に集約してあり、Chrome 拡張とローカルページは
そこに薄い UI をかぶせているだけです。`src/core/` を編集したら
`npm run sync`（または `npm run dev`）を忘れずに。

アイコンは `node scripts/make-icons.mjs` で生成します（生成物は commit 済み。
ビルド時には走りません）。

詳しくは:

- **`CLAUDE.md`** — 開発規約と、踏んではいけない罠
- **`SPEC.md`** — 設計判断の根拠、データモデル、未決事項、ロードマップ
- **`docs/research.md`** — 大学生協・書店ルートの実態調査（2026-08 時点）
