# 調査メモ（2026-08 時点）

実装判断の根拠。ここの前提が変わったら `SPEC.md` を見直すこと。

## 前例

Amazon の書籍ページに外部情報とアクションを注入する Chrome 拡張は既に複数あり、
何年も運用されている。技術的な実現性そのものは検証済みと見てよい。

- [その本、図書館にあります。](https://sonohon.com/)（カーリル製）— Amazon の
  書籍ページに近隣図書館の蔵書・貸出状況を表示する
- [Libron](https://chromewebstore.google.com/detail/libron/fpfgglfemmnflnmjminpghmeiajcajoi?hl=ja)
  — 同様に図書館の予約導線を差し込む

いずれも「ISBN を取る → 外部サービスに問い合わせる → ページに差し込む」という
本プロジェクトと同じ構造。継続的な保守コストは Amazon の DOM 変更に集中する。

## 書誌データ

- [openBD](https://openbd.jp/) — ISBN で書誌と書影を返す。無料・登録不要・
  CORS 許可あり。日本の書籍が対象。**一次ソースとして採用。**
- 未収録（特に古い本・自費出版・洋書）があるため、フォールバックは必要。
- 代替候補: 国立国会図書館サーチ、Google Books API。v0.1 では入れていない。

## 大学生協ルート

**2024 年 12 月に大きな変更があった。**

- 旧「大学生協オンライン書籍注文サイト」は 2024-12-23 に注文受付を終了
  （[案内](https://online.univ.coop/book/)）
- 後継は「オンライン書店 HonyaClub.com（大学生協用）」。日販系の
  [Honya Club](https://www.honyaclub.com/) の生協版で、生協店舗での受取・支払に対応

ただし **公費（校費・研究費・科研費）の扱いは各大学生協の独自運用が残っている。**
確認した範囲でも書式がばらついている:

- [京都大学生協](https://www.s-coop.net/service/book/online/guide.html) —
  注文確定時の備考欄に「校費配達希望／個配」と、財源および予算代表者名を記入
- [大阪大学生協](https://osaka-univ.coop/kouhi/kouhi_326.html) — 別建ての
  「公費 WEB」を持つ
- [法政大学生協](https://www.univcoop.jp/hosei/order/order_104.html) —
  研究費・校費・科研費での購入方法を独自に案内
- [中京大学生協](https://www.univcoop-tokai.jp/chukyouniv-coop/staff/staff_139.html) —
  「校費御用聞きシステム」

→ **結論:** 単一の API に寄せられない。だから設定（`profile.templates` と
`profile.destinations[]`）で吸収し、出力はメールと「備考欄に貼れる 1 行」の
2 通りを用意した。

実務上の注意として、公費は検収の都合で**まとめて発注したほうが事務に喜ばれる**。
「カートに入れる」機能はこのために入れてある。

## 地元書店ルート

- [e-hon](https://www.e-hon.ne.jp/bec/SF/Search)（トーハン系）— 「マイ書店」を
  登録して加盟書店で店頭受取。[くまざわ書店](https://www.kumabook.com/e-hon/)
  や[ブックファースト](https://www.book1st.net/recommend/2024/03/000316.html)
  などが参加
- [Honya Club](https://www.honyaclub.com/)（日販系）— 店舗受取
- ~~honto — 丸善・ジュンク堂・文教堂の店舗受取~~ **honto は紙の本の通販を
  2024 年に終了**（2026-08-07 実査確認）。紙は後継の
  [丸善ジュンク堂ネットストア](https://www.maruzenjunkudo.co.jp/) と
  7net への外部リンクで誘導される構造になっている

いずれも ISBN 検索へのディープリンクは作れるが、**独立系書店はこれらの
ネットワークに入っていないことが多い。** 「地元書店の応援」という動機に
一番合致するのが独立系なので、v0.1 ではメール（＝相手を選ばない手段）に
一本化した。ディープリンクは v0.2 で「速い経路」として足す。

## 対応サイト拡大の実査メモ（2026-08-07）

v0.2 の判断根拠。各サイトの書籍ページで ISBN がどう取れるかを実ページで確認した
（サンプル: 9784478025819）。このツールの致命的故障は「ISBN が取れない」ことだけで、
パネルの差し込み先が消えても floating 表示にフォールバックする設計のため、
評価軸は ISBN 取得経路の DOM 依存度に置いた。

| サイト | ISBN 取得 | 致命リスク |
|--------|-----------|-----------|
| 紀伊國屋ウェブストア | URL 直埋め込み `/f/dsg-01-<ISBN13>`（和書。洋書は dsg-02） | ほぼゼロ（DOM 不要） |
| 丸善ジュンク堂ネットストア | URL 直埋め込み `/products/<ISBN13>`（Shopify 系） | ほぼゼロ |
| 楽天ブックス | URL は内部 ID（`/rb/<数字>/`）。meta タグ + `<title>` 末尾 + 本文に ISBN。本文中の 13 桁は主商品の 1 件のみで誤検出なし | 低（3 経路の冗長取得） |
| honto | 紙の詳細ページが存在しない（上記のとおり通販終了） | 対象外 |

注意: 紀伊國屋は自動アクセス（curl・ヘッドレス）を強く遮断するが、拡張の
content script はユーザーの実ブラウザ内で動くため影響しない。影響するのは
開発時の機械的な事前調査だけで、アンカー選定は実ブラウザで確認する。

## 技術的な制約とリスク

- **Amazon の DOM 変更** — 継続的な保守コスト。前例の拡張も何度か壊れている。
  セレクタを `content.js` の 2 つの配列に集約して被害を局所化してある。
- **クライアント側の表示改変** — 前例が多数あり、実務上は問題になっていない。
  ただし Amazon から取得したデータの保存・再配布はしない。
- **Chrome ウェブストアの単一目的ポリシー** — 「書籍の注文導線を追加する」で
  一貫させる。機能を足しすぎない理由でもある。
- **mailto の長さ制限** — 日本語では 1 文字が 9 文字にエンコードされるため、
  和文の注文メールは 1 冊でも 2000 文字を超える。実測で約 3,000 文字。
  → クリップボード + 件名のみ mailto の 2 段構えで回避。

## 今後効きそうな拡張

- **カーリル API で自大学図書館の蔵書チェック** — 「注文する前に、もう
  図書館にある」を見せる。研究費の無駄が実際に減るので、研究者向けには
  ここが一番刺さる可能性がある。
- **年度末の予算執行アラート** — 3 月の締切前に未発注リストを出す。
